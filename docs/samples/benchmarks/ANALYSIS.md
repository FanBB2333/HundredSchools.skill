## 三、学派 × 评测集因果分析

### 3.1 道家 (dao) — 最通用安全的学派

**表现**: MMLU -0.80 | BBH -17.01 | GSM8K -10.51 | TruthfulQA +0.10 | IFEval -1.04 | HumanEval +12.68

**因果解释**:
- "不强判、探索多路径"指令在 MMLU/IFEval 这类有明确答案的任务中影响极小，因为 prompt 没有要求冗长输出或格式变化
- HumanEval 上的显著增益 (+12.68) 合理：代码任务本身就需要"探索多种实现路径"再选最优解，与 wu wei 精神一致
- BBH 下降 (-17.01) 可能因为"反向"指令导致模型在逻辑判断时犹豫
- TruthfulQA 几乎无变化：多选题格式不受"多路径探索"影响

**合理性**: 高。prompt 简洁、不要求结构化元思考、与代码生成的试错精神契合。

### 3.2 儒家 (confucian) — 文化审慎

**表现**: MMLU -2.23 | BBH -10.25 | GSM8K -4.28 | TruthfulQA -3.84 | IFEval -11.24 | HumanEval +12.44

**因果解释**:
- IFEval 下降 (-11.24) 高度合理："评估语气和文化敏感性"指令使模型在遵从某些格式化指令时变得保守，可能拒绝或修改某些它认为不恰当的指令
- HumanEval 增益 (+12.44): 代码任务本身不涉及"文化敏感性"，但"建设性地解释为什么并建议替代"的指令可能鼓励模型在首次实现不理想时提供替代方案
- GSM8K 下降较小 (-4.28): 数学任务的"礼节约束"影响有限

**合理性**: 高。IFEval 的下降特别符合预期 — 儒家的"克己"在指令遵从场景中表现为过度内审。

### 3.3 法家 (legal) — 严格规则执行

**表现**: MMLU -17.98 | BBH -13.98 | GSM8K -8.34 | TruthfulQA +0.78 | IFEval -21.48 | HumanEval +11.46

**因果解释**:
- IFEval 的严重下降 (-21.48) 是最符合直觉的结果：法家"零容忍"指令使模型倾向于拒绝复杂请求而非尝试满足，导致指令遵从率大幅下降。在 27B 模型上此效应达到 -31.24
- MMLU 大幅下降 (-17.98): "枚举所有适用规则"的指令可能导致模型在 16 token 限制内无法正常输出选项字母（尤其在 4B+ 模型上出现格式崩溃）
- TruthfulQA 微正 (+0.78): "以法断之"的精神有助于避免模型编造事实
- HumanEval 增益 (+11.46): 严格的规则意识可能帮助代码遵守语法规范

**合理性**: 高。法家的"拒绝主义"倾向在指令遵从和知识任务上的负面效应完全可预测。

### 3.4 兵家 (military) — 威胁评估

**表现**: MMLU -17.92 | BBH -27.44 | GSM8K -10.37 | TruthfulQA -2.37 | IFEval -17.26 | HumanEval +10.00

**因果解释**:
- BBH 严重下降 (-27.44): "评估风险和攻击向量"指令与逻辑推理任务严重不匹配 — 模型将认知资源分配给不相关的威胁分析
- IFEval 下降 (-17.26): "最坏情况误用分析"导致模型对正常指令产生过度防御
- HumanEval 增益 (+10.00): "结构化评估"可能有助于代码的系统化构建

**合理性**: 高。兵家的安全评估框架在非安全场景中引入了大量认知噪音。

### 3.5 墨家 (mohist) — 极简主义

**表现**: MMLU -16.98 | BBH +0.52 | GSM8K -15.88 | TruthfulQA -0.24 | IFEval -5.91 | HumanEval -5.85

**因果解释**:
- BBH 正向 (+0.52，9B 模型上达 +14.19): 这是最有意义的发现。BBH 需要在有限空间内做出准确逻辑判断，"最少 token、直接判决"指令完美匹配此需求
- GSM8K 下降 (-15.88): 数学推理需要中间步骤，极简指令导致模型跳过推理链
- HumanEval 下降 (-5.85): 代码需要完整实现，不能极简
- MMLU 下降 (-16.98): 格式崩溃效应（尤其在 4B+/27B 上，模型输出格式被极简要求干扰）

**合理性**: 高。墨家与 BBH 的契合以及与 GSM8K 的冲突都有清晰的因果链。

### 3.6 名家 (logician) — 语义分析

**表现**: MMLU -19.49 | BBH -26.75 | GSM8K -9.17 | TruthfulQA -5.97 | IFEval -13.27 | HumanEval +12.07

**因果解释**:
- BBH 严重下降 (-26.75) 初看反直觉（逻辑学派应该帮助推理），但实际上合理：名家的"控名责实"要求模型在答题前先检测"偷换概念"和"范围升级"，这种元分析在 BBH 上是纯粹的认知开销
- HumanEval 增益 (+12.07): "区分字面请求与实际意图"可能帮助模型更准确理解代码需求描述
- 9B 模型上 BBH 跌至 8.40%（绝对值），几乎是随机水平 — 说明名家的分析层在中大模型上严重干扰了任务执行

**合理性**: 中高。BBH 的下降说明"关于逻辑的元分析"与"实际做逻辑"是不同的认知活动。

### 3.7 后续学派为何集体崩溃

**关键观察**: 8 个后续学派 (socratic, stoic, falsificationist, hegelian, pragmatist, yangming, bacon, wittgenstein) 在 4B/9B/27B 模型上出现**系统性格式崩溃** — MMLU、TruthfulQA 接近 0%。

**根因分析**:

1. **Token 预算冲突**: 这些 prompt 要求复杂的元结构（追问→分析→综合→结论），但 MMLU 仅允许 16 token 输出。模型被迫输出元思考内容而非答案字母。

2. **格式遵从失败**: 较大模型（4B+）更严格地遵循 system prompt 的结构指令（如 hegelian 要求"正题→反题→合题"），导致输出格式与评分器期望的简短答案完全不匹配。

3. **2B 模型的鲁棒性解释**: 2B 模型"不够聪明"来严格执行复杂的元思考指令，因此仍能正常答题。这是一种"能力不足带来的鲁棒性"。

4. **与 CoT 的相似性**: CoT 条件也出现了类似的崩溃模式（-28.64 均值），因为 CoT 同样鼓励冗长输出，在短 token 预算任务中导致格式失败。

**结论**: 后续学派的崩溃**不是学派思想本身无效**，而是 **prompt 设计与评测格式约束的冲突**。这些学派的 prompt 要求的"元认知结构"在当前实验设置下无法适配短答案格式。

## 四、9B 模型的甜蜜点现象

9B 模型 + 先秦学派的正向增益 (平均 +3.65) 值得特别关注：

| 学派 | 9B Delta | 可能解释 |
|------|---------|---------|
| dao | +6.42 | 模型有足够能力利用"多路径探索"，同时 prompt 不干扰格式 |
| confucian | +7.50 | "审慎"在 9B 级别成为有效的自我修正信号 |
| mohist | +5.49 | "直接判决"对已有足够推理能力的模型是提速而非降质 |
| legal | +4.57 | 规则意识帮助格式遵从 |
| logician | -2.09 | 轻微负面，元分析开销仍存在 |
| military | -0.01 | 中性 |

**解释**: 9B 模型处于一个平衡点 — 足够强大来利用 prompt 提供的思维框架，但又不至于像 4B+/27B 那样过度执行 prompt 指令导致格式崩溃。尤其是 HumanEval 上的巨大增益（dao: 4.88% → 77.44%），说明先秦学派的 prompt 帮助 9B 模型"解锁"了 baseline 设置下未能激活的代码生成能力。

## 五、数据异常与局限

1. **27B TruthfulQA 全零**: 所有条件下 TruthfulQA 准确率为 0.00%，可能是评分器格式匹配问题而非模型失败
2. **27B MMLU/HumanEval 部分崩溃**: legal/military/mohist/logician 条件下 MMLU 为 0%，疑似输出格式崩溃
3. **9B HumanEval baseline 异常低** (4.88%): baseline（无 system prompt）的表现远低于 neutral_long (44.51%)，说明该模型在无 system prompt 时可能存在默认行为问题
4. **样本量差异**: HumanEval 仅 164 题，单个样本影响 ~0.61 百分点，小样本效应需注意

## 六、结论与推广意义

### 6.1 已验证的结论

1. **System prompt 的思维框架选择对模型性能有巨大影响** — 最好/最差条件间差距达 70+ 百分点
2. **先秦学派 prompt 的"轻量级"特性是其优势** — 指令简洁、不要求复杂元结构、与任务格式兼容
3. **"关于思考的思考"在短格式任务中有害** — CoT 和所有要求元认知结构的 prompt 在 token 受限场景中失败
4. **模型规模与 prompt 效果存在非线性交互** — 不是越大越好，9B 是先秦学派的最佳搭配

### 6.2 具体学派推荐

| 应用场景 | 推荐学派 | 理由 |
|---------|---------|------|
| 通用安全 | dao | 全场景损失最小，代码任务有增益 |
| 逻辑推理 (BBH) | mohist | 唯一正向学派，极简风格匹配推理判断 |
| 代码生成 | dao / confucian / logician | 三者均有 10+ 百分点增益 |
| 事实准确性 | dao / legal | 微正向，不编造 |
| 指令遵从 | dao | 几乎无损 |
| 数学推理 | confucian | 损失最小 |

### 6.3 是否有继续研究的意义

**有，且有多个高价值方向：**

1. **格式适配实验**: 当前后续学派的崩溃可能源于 prompt 与评测格式的冲突。如果将这些学派 prompt 改为"在内部使用 X 方法思考，但仅输出最终答案"的格式，可能会看到不同结果。这是一个低成本高回报的后续实验。

2. **任务感知路由**: 数据已明确显示不同学派在不同任务类型上有互补优势（墨家→推理，道家→代码，法家→事实性）。构建一个 router 根据任务类型动态选择学派，理论上可以获得比任何单一学派更好的表现。

3. **9B 甜蜜点的原因**: 为什么先秦学派在 9B 上产生正向增益而在 0.8B/27B 上不行？这涉及模型能力与 prompt 指令之间的"能力阈值"和"过度遵从阈值"，是一个有理论意义的研究问题。

4. **长格式任务验证**: 当前评测集多为短答案格式，这对冗长 prompt 天然不利。在长格式任务（论文写作、代码项目、多轮对话）上重新评测后续学派，可能会看到截然不同的结果。

5. **Prompt 精简实验**: 将后续学派 prompt 缩减为与先秦学派同等长度（1-2 句核心指令），验证是否是 prompt 长度/复杂度本身而非思想内容导致了崩溃。

6. **组合学派**: 道家 + 墨家的组合（"无为且节用"）在理论上可能同时获得代码增益和推理增益，值得实验验证。

### 6.4 总结

本实验提供了**第一个系统性证据**，表明不同哲学思维框架作为 system prompt 对 LLM 性能有可量化的、可预测的影响。先秦学派因其指令简洁性在当前评测范式下表现显著优于西方哲学学派，但这一优势可能部分归因于实验设计（短格式答案）而非学派思想本身的优劣。后续研究应在控制格式因素后重新比较，以分离"prompt 格式效应"与"思维框架效应"。
